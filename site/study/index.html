How much of popular open-source code is AI-written?

A study of 18 well-known repositories · 2026-11-27 · measured with grokmap 0.2.0
Key findings
  • In 3 of 18 projects, most commits from August to October 2026 were co-authored by an AI coding agent: modelcontextprotocol/servers (94.2%), microsoft/vscode (74.1%), github/github-mcp-server (69.3%).
  • 12 of 18 projects mark a larger share of their commits as AI co-authored now than in 2025.
  • Across GitHub, more than 12.4 million public commits carry a Co-Authored-By: Claude trailer alone.
  • The visible numbers depend heavily on each project's commit conventions. Several projects that certainly use AI tools show near zero, because their commits don't carry agent markers. Read these as a lower bound.

Why this matters

Writing code is no longer the bottleneck; understanding it is. When most new commits in a project are co-authored by an agent, the question that matters for maintainers is not "who typed this?" but "does anyone here understand it well enough to debug it?". That gap is comprehension debt, and it is invisible in the usual metrics. This study only measures the first half, AI involvement. The second half, understanding, can't be seen from outside a team, which is why grokmap pairs these numbers with an opt-in ledger of quiz results.

Method

  • Repositories: 18 widely used open-source projects across editors, developer tools, AI frameworks and agent tooling, chosen for popularity and active development, not for known AI use. Default branch, non-merge commits, 166,365 commits since January 2025.
  • Detection: grokmap's built-in signatures: co-author trailers (Co-Authored-By: Claude, Co-authored-by: Copilot, Codex, Cursor, Charm Crush and others), agent bot authors (Copilot coding agent, Devin, Jules…), and footers such as "Generated with Claude Code". The full list is in detect.py.
  • Line attribution: git blame -w at HEAD, ignoring blank lines and lone punctuation, with grokmap's default exclusions (lock files, build output, vendored code, media).

Limitations (please read before quoting)

  • Co-authored is not the same as written. A trailer says an agent took part in a commit, not how many of its lines the agent produced. In squash-merged pull requests, a single accepted Copilot review suggestion can add a Co-authored-by: Copilot line to a commit that is otherwise human work, and blame then attributes the whole commit to the agent. One example: a large "v1.0" squash merge in goose credits a dozen people plus Copilot.
  • Absence of markers is not absence of AI. Projects that squash commits with edited messages, or whose agents don't add trailers, show low numbers regardless of actual use. Drops (for example openai/codex and oven-sh/bun) most likely reflect changed commit conventions, not less AI use.
  • Conventions vary by tool. Copilot-heavy projects like VS Code add a co-author line whenever agent edits are included in a commit, which is more systematic than most other workflows. Comparisons across projects say as much about conventions as about AI use.
  • Snapshot. Data collected on 2026-11-27. Numbers will change; the method is reproducible below.

Reproduce it

pipx install grokmap
git clone https://github.com/modelcontextprotocol/servers && cd servers
grokmap status            # share of current lines from AI co-authored commits
grokmap trend --by month  # AI vs human lines added per month, by agent

The raw numbers behind this page are in data.json. If you maintain one of these projects and think a number is misleading, please open an issue and it will be corrected.
